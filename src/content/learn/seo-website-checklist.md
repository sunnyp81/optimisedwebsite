An SEO checklist for a new website has 30 checks in five phases: plan, build each page, test on staging, launch day and the first 28 days. Each check below has a pass test so you know when it is done.

A new site has no rankings to protect. The job is to make every page easy for Google to find, read and index from day one. Replacing a site that already ranks? Use the [website redesign SEO checklist](/learn/website-redesign-seo-checklist/) because it adds the redirect work.

## Phase 1: Plan the Site (5 Checks)

Plan before design starts. These five checks decide what gets built.

1. **Add the domain to Google Search Console and Bing Webmaster Tools.** A Domain property is verified with a DNS record at your domain provider. See Google's <a href="https://support.google.com/webmasters/answer/9008080" target="_blank" rel="noopener noreferrer">verification guide</a>. Pass: both tools show the property as verified.
2. **Give each page one main query.** List every planned page beside the search query it answers. Pass: one row per page and no query appears twice.
3. **Settle the URLs.** Google's <a href="https://developers.google.com/search/docs/fundamentals/seo-starter-guide" target="_blank" rel="noopener noreferrer">SEO Starter Guide</a> recommends words in the URL that are useful to people. Choose lower case and one rule for trailing slashes. Pass: every planned URL is readable and follows the same rule.
4. **Plan the links between pages.** Each page needs a link from its parent page and from one related page. Pass: the plan shows no page without an inbound link.
5. **Define an enquiry and plan the tracking.** Decide which actions count: a form sent, a phone tap or an email click. Pass: each action has a named event in your analytics plan.

## Phase 2: Build Each Page (7 Checks)

Run these on every page template and every page of copy. The table shows what a pass and a fail look like for four of them.

| Element | Passes | Fails |
|---|---|---|
| Title | Names the page topic in words a searcher uses | "Home" or one title repeated on every page |
| Opening | Answers the query in two sentences | Starts with company history |
| Link text | "boiler repair prices" | "click here" |
| Alt text | "Engineer fitting a combi boiler under a kitchen worktop" | "image1.jpg" |

6. **Write a unique title.** Google describes a good title as unique to the page, clear, concise and accurate. Pass: a crawl shows zero missing or duplicate titles.
7. **Write a meta description.** Keep it short and unique. Include the most relevant points of the page. Pass: a crawl shows zero missing or duplicate descriptions.
8. **Use one clear main heading and descriptive subheadings.** Google says heading order does not matter for Search. A logical order still helps people who use screen readers. Pass: the headings read alone as an outline of the page.
9. **Open with the answer.** Google says content length alone does not matter for ranking. Pass: the first two sentences answer the page's main query.
10. **Describe every content image.** Alt text explains the image and how it relates to the page. Set width and height so the layout does not jump. Pass: no content image is missing alt text.
11. **Link with descriptive text.** Link text tells people and Google what the target page is about. Follow an [internal linking strategy](/learn/internal-linking-strategy/) for the cluster. Pass: no link reads "click here" and every page has one contextual link pointing at it.
12. **Add structured data that matches the visible page.** Google's <a href="https://developers.google.com/search/docs/appearance/structured-data/sd-policies" target="_blank" rel="noopener noreferrer">structured data guidelines</a> say not to mark up content readers cannot see. Valid markup does not guarantee a rich result. Pass: the Rich Results Test shows zero errors on each template that uses a type eligible for rich results.

## Phase 3: Test on Staging (8 Checks)

Staging is a private copy of the new site. Fix faults here before anyone can find them.

13. **Password-protect the staging copy.** A noindex rule alone leaves the pages public. Do not rely on robots.txt either. Google's <a href="https://developers.google.com/search/docs/crawling-indexing/robots/intro" target="_blank" rel="noopener noreferrer">robots.txt introduction</a> says the file is not a way to keep a page out of Google. Pass: every staging page asks for a password.
14. **Force HTTPS on one host.** Pick the www or the bare domain. Pass: the http, www and non-www variants all end at one HTTPS URL and none needs more than one redirect.

15. **Point each canonical at the live address.** A canonical left on the staging domain is a common launch fault. Pass: the canonical on 10 key pages matches the URL each page will have when live.
16. **Check robots.txt.** It should allow the pages you want crawled and name the sitemap. Pass: no wanted page is disallowed and the Sitemap line is present.
17. **Build the XML sitemap.** List only pages you want indexed. Google's <a href="https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview" target="_blank" rel="noopener noreferrer">sitemap overview</a> says a new site with few external links may need one. Pass: every sitemap URL returns 200 and none is redirected or set to noindex.
18. **Crawl the staging copy.** Use a crawler such as Screaming Frog or Sitebulb. Pass: zero internal links to 404s or redirects and a made-up URL returns a 404 status.
19. **Run a lab speed test on mobile settings.** PageSpeed Insights cannot reach a password-protected page, so run Lighthouse in Chrome DevTools on staging. Google's <a href="https://developers.google.com/search/docs/appearance/core-web-vitals" target="_blank" rel="noopener noreferrer">targets</a> are Largest Contentful Paint of 2.5 seconds or less, Interaction to Next Paint of 200 milliseconds or less and Cumulative Layout Shift of 0.1 or less. Lab tests are only a guide. The real pass comes from visitor data at check 30. The guide to [site speed and Core Web Vitals](/learn/site-speed-and-core-web-vitals/) explains each measure. Pass: Lighthouse shows LCP and CLS in range for each template.
20. **Check phones and contrast.** Open each template on a phone. Normal text needs a contrast ratio of 4.5 to 1 under WCAG AA. Low contrast is the most common failure in our website accessibility statistics. Pass: no sideways scrolling and no text below the ratio.

## Phase 4: Launch Day (5 Checks)

Launch day is short. The main risk is a staging block left switched on.

21. **Remove the staging block.** Google's <a href="https://developers.google.com/search/docs/crawling-indexing/block-indexing" target="_blank" rel="noopener noreferrer">noindex documentation</a> says noindex works as a meta tag or as an HTTP response header. Check both on every page meant to be public. Pages you excluded on purpose stay excluded. Pass: each public page returns 200 to a logged-out request with no noindex in either place.
22. **Read the live robots.txt.** Pass: no rule blocks a page or folder meant to be public.
23. **Submit the sitemap** in Google Search Console and Bing Webmaster Tools. Pass: both report it as read.
24. **Inspect the key pages.** Run the homepage and main service pages through URL Inspection and request indexing once. Google says <a href="https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl" target="_blank" rel="noopener noreferrer">repeat requests do not speed up crawling</a>. Pass: the live test reports each URL as available to Google.
25. **Test the tracking.** Send a test enquiry through a form you own. Pass: the event appears in your analytics real-time report.

| Launch item | Who checks | Pass test |
|---|---|---|
| Staging block removed | Developer | Each public page returns 200 logged out with no noindex in meta tag or header |
| Live robots.txt | SEO | No rule blocks a public page or folder |
| Sitemap | SEO | Read by Google and Bing |
| Key pages | SEO | URL Inspection live test reports each URL as available |
| Tracking | Owner | Test enquiry recorded |

## Phase 5: The First 28 Days (5 Checks)

A new site starts with no data. These checks confirm Google is finding the pages.

26. **Day 1: crawl the live site.** Pass: zero broken links and no link or canonical pointing at the staging domain.
27. **Day 3: check index status.** Open URL Inspection for the homepage and main service pages. Google says crawling can take from a few days to a few weeks, so "URL is not on Google" is normal this early. Pass: each page is indexed or has a recheck date for day 7.
28. **Day 7: open the Page indexing report.** Pass: every reason listed for a page not being indexed is either expected or has an owner.
29. **Day 14: compare queries with the plan.** Open the Performance report and set it beside the list from check 2. Pass: a note per page saying whether it has impressions yet.
30. **Day 28: review and fix.** Check the Core Web Vitals report in Search Console. It uses real visitor data and Google's <a href="https://support.google.com/webmasters/answer/9205520" target="_blank" rel="noopener noreferrer">report guide</a> says a new property may show no data yet. Pass: a short written list of fixes with dates.

Give changes time. Google's SEO Starter Guide says some changes take effect in a few hours and others take several months. The guide on [how to rank a new website](/learn/how-to-rank-a-new-website/) covers what to build after launch.

## What You Can Leave Off the Checklist

Long SEO checklists often carry items Google says it does not use. Each row below comes from Google's <a href="https://developers.google.com/search/docs/fundamentals/seo-starter-guide" target="_blank" rel="noopener noreferrer">SEO Starter Guide</a> unless another source is named.

| Item on many checklists | What Google says |
|---|---|
| Keywords meta tag | Google Search does not use it |
| A minimum word count | Content length alone does not matter for ranking |
| Strict heading order for ranking | Heading order does not matter for Search |
| A score of 100 on PageSpeed Insights | The Core Web Vitals page sets three thresholds and no score out of 100 |

## Basic SEO Checklist: 8 Checks to Do First

Short on time? Check these eight before launch.

| Check | What it prevents |
|---|---|
| 1. Verify the domain | No Search Console data on indexing or queries |
| 2. One main query per page | Two pages competing for one search |
| 6. Unique titles | Pages that look the same in results |
| 9. Open with the answer | Pages that miss the query |
| 14. HTTPS on one host | Several copies of one site |
| 21. Remove the staging block | A live site hidden from Google |
| 23. Submit the sitemap | Slow discovery of new pages |
| 24. Inspect the key pages | Indexing faults found weeks late |

## Which SEO Checklist Do You Need?

The right checklist depends on what the site already has.

| Your situation | Use | Why |
|---|---|---|
| New site on a new domain | This checklist | Nothing to protect and everything to set up |
| Redesign or platform change on a site that ranks | [Website redesign SEO checklist](/learn/website-redesign-seo-checklist/) | Old URLs need a baseline and a redirect map |
| Rankings fell after a move | [Recover rankings after a site migration](/learn/recover-rankings-after-site-migration/) | The faults are found by comparing old and new URLs |
| Live site that was never checked | Phases 2, 3 and 5 of this checklist | They work as a website optimisation checklist on a live site |

## Getting the Checklist Done

Checks 13, 15 and 21 are the ones that can hide a finished site from Google. A staging block left on or a canonical left on the staging domain does it without any visible error.
